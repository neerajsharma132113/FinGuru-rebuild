# FinGuru

A personal finance app I am building step by step to learn backend, frontend and applied ML.
It uses synthetic data only. Nothing here is financial advice.

## Status

**Built and tested:**
- Finance engine: EMI, amortization schedule, loan affordability, monthly summary
- Digital Twin scenarios: income change and new loan, each with a before/after comparison
- Next Best Action: rule-based (HELP, WARN, SAVE, NO ACTION), each result includes a reason and the numbers behind it
- Backend: FastAPI, SQLite (money stored as integer paise), Pydantic validation
- Security: Argon2 password hashing, JWT login, protected endpoints, per-user data isolation, login rate limiting (5 failures, 15-minute lock), CORS limited to the dev frontend
- Frontend: React + Vite, dark theme, sidebar screens (Overview, Transactions, Loans, Simulate, Fraud), income vs expenses chart
- ML: synthetic fraud dataset, baselines, Logistic Regression and Isolation Forest, threshold tuning on a validation set, model served at `/fraud-score`
- Automated backend tests with pytest (run `python -m pytest` in `backend`)

**Planned, not built yet:**
- RAG financial knowledge assistant, LangGraph workflow, MCP tools
- Edit and delete for transactions, loading states in the UI
- Database migrations, Docker, deployment

## Fraud model results (synthetic data)

Data: 10,000 generated transactions, 2% fraud, fixed seed. Test set: 2,000 rows with 40 fraud cases.

| Approach | Precision | Recall | PR-AUC |
|---|---|---|---|
| Rule: amount above 3000 | 0.185 | 0.375 | 0.319 |
| Isolation Forest (unsupervised) | 0.698 | 0.75 | 0.794 |
| Logistic Regression, threshold 0.5 | 0.308 | 0.90 | 0.862* |
| Logistic Regression, tuned threshold 0.95 | 0.78 | 0.80 | n/a |

*Measured in an earlier run on the full training set. Precision and recall for Logistic Regression come from the run with a separate validation set.

How to read this:
- The data is generated by me, so the fraud patterns are my own assumptions. These numbers show the workflow, not real-world fraud accuracy.
- With 40 fraud cases in the test set, one case changes recall by 2.5 points.
- The threshold was chosen on 32 validation fraud cases and was the last value in my search grid.
- Isolation Forest was told the true fraud rate (`contamination=0.02`), which would be unknown in real life.
- A flag means "review this transaction". The app never blocks anything.

## Run locally (Windows PowerShell)

Backend:

```powershell
uv venv --python 3.11 .venv
.venv\Scripts\Activate.ps1
cd backend
uv pip install -r requirements.txt
Copy-Item .env.example .env
```

Put a long random value in `.env` as `SECRET_KEY`. Generate one with:

```powershell
python -c "import secrets; print(secrets.token_hex(32))"
```

Create the fraud model (from the project root):

```powershell
uv pip install -r ml\requirements.txt
python ml\generate_data.py
python ml\train_final.py
```

Start the API (from `backend`), then open http://127.0.0.1:8000/docs :

```powershell
python -m uvicorn app.main:app --reload
```

Frontend (second window):

```powershell
cd frontend
npm install
npm run dev
```

Open http://localhost:5173

## Run tests

```powershell
cd backend
python -m pytest -v
```

## Known limitations
- Login rate limiting is in memory: it resets on restart and is per email only (no IP limit)
- The access token lives in memory, so refreshing the page logs you out; tokens cannot be revoked
- The dev database has no migrations
- The fraud model is trained on synthetic data and has not been tested on real transactions
- Next Best Action thresholds (40% EMI share, 3-month emergency fund) are assumptions, not professional advice
